# 大规模测试输入与模型配置

## 大输入的处理范围

正式输入与输出文件支持各最多 4 MiB；全部应用文件合计最多 8 MiB。标程、验证器和模板等代码文件仍各限 256 KiB。可信生成器的回放伴随文件 `generator-data.b64` 是数据文件，限 4 MiB，并计入总量。

正式标程和模板执行显式请求答案数据额度，通过 go-judge 缓存文件取回完整 UTF-8 输出；单个答案最多 4 MiB，一次调用取回的答案合计最多 8 MiB，缓存随后清理。普通运行、独立验证器和压力生成器保留原默认输出限制。输入、输出及辅助文件仍在组装时一起核对整批上限，不通过减少查询或截断正确答案绕过限制。

Python 模板在外围制品阶段及恢复任务物化前接受沙箱内的语法树检查，拒绝模板重定义或通过赋值、导入覆盖已有顶层函数/类。它是静态结构检查，不执行模型源码；最终模板运行也重复检查，正式测试点、样例及独立对拍仍全部执行。检查不能替代运行验证，也不声称穷尽动态 Python 行为。

正式 Python 生成器的 JSON 输出通过 go-judge 缓存文件读取，最大 8 MiB；读取后立即尽力删除已返回的缓存。超限、无效 JSON、执行失败或取消都不会把部分输入当作完整结果。普通程序 stdout 及压力生成器仍保持原有限制；60 组压力数据、独立验证、validator、模板和区分度验证不减少。

可信 GeneratorPlan 单集合支持最多 200000 个元素，所有 CASE 的生成工作量合计仍限 1000000。大回放数据不能压进小脚本时，下载或保存 `generator.py` 和 `generator-data.b64`，置于同一目录后运行。伴随文件保存原始 base64 数据，不添加代码注释。

生成结果继续保存在任务中供教师预览。应用时，未编辑的文件按已授权任务中的文件名引用；改过的文件提交教师的实际内容。当 JSON 转义会使请求超过 Hydro 的 8 MiB JSON 限制时，前端自动使用原始文件上传，服务端仍逐个检查权限、类型、UTF-8、规范化后的大小及总量。任务引用不允许读取其他用户、其他题目或未完成任务的文件。

这些限制是资源预算，不是题面约束。必要覆盖仍超过预算时，系统应明确要求人工复核，不能截断输入、删除测试点或把缩小必要规模算作完成。完整验证与答案抽查分别报告；传输成功并不意味着题目算法正确。旧 v10 及更早提示词检查点需要重新生成，已生成或应用的数据不迁移。

生成器必须先按整批覆盖计划分配规模，并同时估算输入、查询产生的输出与辅助文件大小。单个 `.out` 实测超出 4 MiB、或仅 `.in/.out` 已合计超过 8 MiB，均交给生成器角色定向修复输入构造，保留标程、独立验证器和 frozen Spec；更换标程语言、截断答案或删除测试点不能解决预算问题。生成器断言报告的整批超限与逐点输入大小只作为修复线索，最终接受仍依据服务器实测和全部验证。

可信回放数据与 `.in` 同时保存，会额外占用整批额度。输入与回放伴随文件已经超限时，在压力数据、输入验证和标程执行前停止；输出得到后，沿用实际文件组装逻辑计入模板、代码用途注释、编译脚本、已有配置的编号和回放文件，再执行后续验证。辅助代码单文件超限仍需复核对应制品，不把它误交给生成器缩减输入。总量超限沿用有界生成器修复，既有模型与累计沙箱预算不增加。

可选的补充反例只有在全部文件仍能装入预算时才会加入。超出余量的候选不改变已接纳的测试点，也不标记对应错误解已被识别；同批后续候选仍会检查，均无法接纳时该目标保留预算缺口。最终保存前仍复核各文件、总量和序列化文档上限。

初始标程和修复响应均要求 `ORACLE_LANG` 声明 `python` 或 `cpp`；定向修复会同时更新代码与语言。旧的未声明 Python 响应仍兼容；未声明但具有明确 C++ 起始语句的传统题程序会识别为 C++，仍须通过沙箱编译能力检查。未知或冲突声明、Python 声明配 C++ 源码、以及函数题 C++ 标程会被拒绝，不能靠改标签进入 Python 执行器。执行失败保留实际语言，导出的 `std.py` / `std.cc` 与执行语言一致。

缓存接口依据 [go-judge 官方 API](https://docs.goj.ac/api)；Hydro 的请求体和上传生命周期依据项目所用 `@hydrooj/framework/server.ts` 实现核对。

## 非法输入证明与连续修复

题意提取提示提供可直接解析的合法 JSON 示例，将枚举说明和可选字段规则放在示例之外。非浮点输出省略 `tolerance`；没有可定位标题时省略 `evidence.section`；区间的 `operation-argument:l/r` 声明为每次操作的整数参数，不作为整列数组。服务端不自动转换错误类型、删除字段或放宽契约。

冻结规范前，每个提取角色仅在严格格式检查失败时最多重新提取一次，收到完整题面与服务器固定字段提示。错误响应和其他角色的规范不会被转发；再次返回的结果仍接受全部结构、引用和题面证据核验。缺失证据、端点失败、取消及预算耗尽不触发格式重试，已返回调用的用量继续统计。

服务器构造的非法输入也按数据计量：每份最多 4 MiB，单次非法验证批次合计最多 8 MiB，包括未知子任务和非法参数协议检查。预算内无法完成的检查保留为缺口；不能用同一目标的另一次拒绝掩盖未构造的探针。

约束解释支持有限的等价写法：唯一且不与其他 ID 冲突的字段名、`len(a) == n` / `length(a) = n`，以及 `a[i]` 或 `forall i: a[i]` 的整数上下界。解释仅用于探针，不修改 frozen Spec、题面引文和哈希。自然语言约束和不支持的表达式继续明确保留缺口，不执行表达式代码。

探针按稳定顺序最多尝试 64 个适用样本。构造前按适用范围预检这批有界候选，后面的已知非法样本也不能被前面成功构造的反例掩盖；未知语义仍不擅自解释。首个样本太大或不能构造目标反例时可尝试后续样本；若已能证明某个被验证器接受的样本非法，则保留缺口。子任务探针只能使用对应子任务的正式样本。检查数组计数字段越界时，同步维护已识别的数组长度关系，再确认只违反目标约束；超过额度或破坏其他已识别约束时拒绝计作证据。

每次生成的物化阶段最多定向修复两个不同制品，同一制品不重复修复。这样修好压力生成器后，新暴露的暴力解错误仍有一次机会；后续请求使用当前独立验证器内容，不把标程实现交给验证角色。完整修复回退也消耗次数，原模型调用预算、累计沙箱预算、取消和不可重试策略继续生效。修复后只复用依赖仍有效的结果，验证器修改仍使依赖其结果的检查失效。

## 如何帮助管理员选择模型

分工指不同角色可以调用不同模型；没有单独设置的角色继承测试数据生成场景的模型链。当前管理页支持六个角色的独立模型链，本次大输入改动不改变配置界面或默认模型。

| 角色 | 选择依据 |
| --- | --- |
| 题意主提取 | 能准确提取约束、样例和输入编码，并稳定返回结构化内容 |
| 标程 | 编程与算法能力，尤其是最大规模的正确性和复杂度 |
| 题意复核、独立验证 | 能发现遗漏与反例；与被复核方使用可区分的模型身份 |
| 外围制品 | 输入协议、模板和有界生成的稳定性；通过测试后再比较速度与费用 |
| 分歧裁决 | 能依据题面证据判断冲突，而非简单投票 |

建议后续产品把基本配置收敛为“主模型”和“独立验证模型”，其余角色默认继承相应配置；六角色和备用链保留为进阶设置。界面检查应包含实际生效的继承链、端点可用性和当前可检测的模型身份冲突。不同名称或端点不保证底层模型真的独立，因此只能说明可验证的配置事实。

推荐配置需要标明测试日期、端点、模型版本、题型、样本量、产物检查通过率、完整验证通过率及成功任务耗时。一次最小请求只能证明端点可调用，不能证明算法能力；失败提前结束不能记作提速。只在有足够同题重复测试后提供“已验证推荐”，未测试的组合明确标为“自定义、未验证”。

本次此前的 Pro/Flash/Sonnet 分工实验只有求和产物通过外部检查，另外三题失败，且求和仍未通过完整验证。因此它是候选方案，不能直接设为面向用户的默认推荐。本次未修改在线模型配置。

区间操作与字符串拒绝证据支持固定前缀后的操作行、ASCII token 字符串长度、二进制字符集，以及每种操作的左端点下界、左右次序和右端点上界。计数边界反例保留已识别的字符串长度及操作行数，所有反例仍逐项检查目标隔离和 4 MiB / 8 MiB 预算。额外状态前置条件、重叠字段、模糊布局和 Unicode 长度单位保留缺口。

操作的前置条件本身也参与隔离检查，不依赖约束列表中的重复声明；可识别的区间条件逐项验证，未知前置条件使反例保持未证明。字符约束只覆盖其原索引范围，不能把前 n 个字符的要求扩大到整个字符串。不同操作在不同样本的同一行出现时，反例标识仍分别保留。

当 q >= 1 且每条操作必须满足 1 <= l <= r <= n 时，n = 0 无法只违反 n 下界；已有 n 上界拒绝证据也不能把整项计为完整验证。系统保留该构造缺口，不能用同时违反端点约束的输入冒充独立证明。
